# LogiTrack: реализация пяти этапов аудита

Ветка: `fix/dispatch-and-billing`, база: `dev` (`c2cdf61`). Это рабочая демонстрационная реализация для проверки продуктовых сценариев. По согласованию внешние интеграции используют адаптеры и тестовые пакеты; провайдеры пока не выбраны.

## Что изменилось

| Этап | Реализованное поведение |
| --- | --- |
| 1. Достоверность данных | Подтверждённые мили и заработок отделены от прогноза; будущий backhaul не увеличивает начисления и фактическую выручку. Неизвестный пробег отмечается явно. Повторные RateCon распознаются в пределах брокера, изменения сохраняются как версии с различиями. Назначение повторно проверяется по актуальному состоянию. |
| 2. Документы и расчёты | POD можно загрузить, открыть и подтвердить в офисе. Рахунок хранит строки, срок оплаты и ссылки на проверенные документы. Есть частичные платежи, история, просрочка, защита от переплаты и повторного выставления. Согласованный простой добавляется отдельной строкой; после выставления — дополнительным счётом. Номинал, комиссия, аванс и резерв факторинга учитываются отдельно от оплаты клиентом. |
| 3. Техника и планирование | Справочник тягачей/прицепов, тип кузова, длина, грузоподъёмность, срок осмотра, ремонт и доступность. Проверяются занятость, совместимость и временные окна. Перепризначение запланированного рейса требует причины и сохраняет запись в журнале. Площадки имеют контакт, телефон, часовой пояс и инструкции въезда. |
| 4. Кабинет водителя | Экран «Моє завдання та виплати»: собственные грузы, адреса, время, инструкции, статусы, POD, сообщения по грузу, запрос простоя, расчётный лист и начисления/удержания с основанием. Передрейсовый осмотр содержит 13 пунктов и фотографии; неустранённые дефекты блокируют выпуск. Финансовое подтверждение остаётся у менеджера. |
| 5. Адаптеры | Импорт платежей, GPS, ELD, топлива и пробега по штатам. Пакет проверяется до применения; внешние id предотвращают повторы, старые GPS/ELD не заменяют более свежие данные. Есть журнал обмена, CSV счетов/платежей/топлива и сводка по штатам. |

Обзор разделяет план, доставленную выручку, документы, неоплаченные и просроченные счета. На карте план маршрута отделён от последней GPS-позиции, указаны источник и время. Простой рассчитывается по фактическому интервалу, бесплатному времени и ставке; для начисления нужны одобрение и ссылка на согласование клиента.

В назначении учитываются часовые пояса, фиксированное время и FCFS, порожний переезд, отдых и расчётное опоздание. Даты водителя/осмотра проверяются на дату pickup. Неоднозначное или несуществующее время перехода на летнее время отклоняется.

Загрузка POD и фото использует общий элемент «Обрати POD» / «Обрати фото». На мобильном кнопка занимает ширину поля; имя файла переносится без горизонтального переполнения. Системные английские подписи убраны.

## Как посмотреть

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

Открыть `http://127.0.0.1:5174/`. Быстрый вход на экране входа: Sarah Jenkins — менеджер, Alex Mercer — диспетчер, Marcus Hill — водитель. Водитель открывает «Моє завдання та виплати» (`/my-work`), офис — «Клієнти та рахунки», «Техніка та огляди», «Інтеграції».

Дата демонстрации фиксирована: **28 октября 2026 года**, расчётная неделя 26 октября — 1 ноября. Тестовые сроки оплаты и GPS/ELD относятся к этому дню. Существующие пользовательские данные localStorage мигрируют, а не сбрасываются автоматически.

### Сценарии приёмки

1. У Marcus открыть расчётный лист. Подтверждённый пробег исходного рейса — 880 миль, начислено $572 при $0.65/милю. Прогноз полного маршрута показан отдельно. Назначение будущего обратного груза меняет прогноз, но не заработок за сегодняшний день.
2. В чистом наборе данных счёт LT-00001 на $950 открыт полностью. Зарегистрировать платёж $400 с уникальным референсом: получено $400, остаток $550. Попытка записать ещё $600 отклоняется.
3. Повторно импортировать тот же RateCon и назначить его из двух вкладок. Дубль не создаётся; конфликт устаревшей версии возвращает актуальные данные и просит повторить действие после проверки.
4. Открыть Hart: загруженный демонстрационный POD требует проверки офиса. Водитель не может подтвердить POD или выставить счёт. После подтверждения офис может выставить счёт с привязанным документом.
5. Создать запрос простоя с интервалом, бесплатным временем и ставкой; менеджер подтверждает его с референсом согласования клиента. Повторное подтверждение не удваивает доплату.
6. В «Техніка та огляди» отметить дефект, сохранить осмотр, проверить блокировку назначения. Менеджер фиксирует устранение с описанием; после этого техника снова может использоваться.
7. В «Інтеграції» выбрать GPS, импортировать и повторить: второе применение не создаёт запись. Аналогично доступны тестовые платежи, ELD, топливо и мили по штатам. Если вручную уже внесён платёж $400, учесть остаток долга перед импортом платёжного пакета.

В локальном preview, использованном для проверки, оставлен тестовый платёж `QA-PARTIAL-400` и одна GPS-позиция, поэтому остаток LT-00001 уже равен $550. Тесты каждый раз используют изолированный исходный набор данных.

## Хранение и одновременная работа

При `npm run dev` Vite подключает локальное API `/api/workspace` и `/api/documents/:id`. Общие данные сохраняются в игнорируемом Git каталоге `server/.data/audit-review`. Сохранение снапшота сериализовано, использует ревизию и атомарное переименование файла. Второй писатель с устаревшей ревизией получает HTTP 409. Клиент не дублирует платёж при потере ответа после успешного сохранения; отклонённые HTTP 422 не отправляются бесконечно.

PDF/PNG/JPEG проверяются по сигнатуре, максимальный размер — 10 МБ. В dev файл хранится на локальном сервере и доступен другим вкладкам после синхронизации. Статическая сборка без API работает локально: бизнес-данные — в localStorage, файлы — в IndexedDB этого браузера. Подпись вверху страницы показывает режим синхронизации. Учётная запись и навигация не пересылаются через общий снапшот.

Это локальный сервис для проверки, **не production backend**: роли и вход остаются демонстрационными; сервер не предоставляет настоящую авторизацию, изоляцию перевозчиков или защищённый доступ водителя к данным. Для публичной эксплуатации потребуются серверные сессии/права, база данных с транзакциями, закрытое файловое хранилище и миграция событий вместо общего снапшота. Существующая отдельная backend-ветка с незавершёнными изменениями не объединялась с этой работой.

## Ограничения расчётов и интеграций

- GPS/ELD, бухгалтерия и топливные карты пока не обращаются к реальным сервисам. JSON-контракт `{ id, provider, kind, records }` и примеры находятся в `src/integrations/fixtures.ts`; проверка и нормализация — в `adapters.ts`. Ключи провайдеров не нужны.
- Время движения/отдыха — модель планирования, не сертифицированный HOS-движок. Она использует базовые ориентиры 11 часов движения, 10 часов отдыха и перерыв после 8 часов; свежие ELD-показатели ограничивают доступный ресурс. Полный контроль 14-часового окна, циклов, исключений и реального журнала требует выбранного ELD-провайдера. Основание ориентиров: [FMCSA Summary of Hours of Service Regulations](https://www.fmcsa.dot.gov/regulations/hours-service/summary-hours-service-regulations).
- Пробег по штатам и топливо служат для сверки; ставки налогов и декларация IFTA не рассчитываются.
- Демонстрационные POD обозначены как образцы. Рейтинги брокеров содержат источник и дату проверки либо явное указание, что внешняя проверка не задана.

## Проверки

```sh
npm test -- --run
npm run lint
npm run build
```

Результат: **82 теста проходят**, lint без ошибок, TypeScript/Vite-сборка успешна. Новые сценарии покрывают P0, роли, POD/простой, технику, переназначение, временные зоны, импорты, конкурирующие записи, перезапуск хранилища, потерянный ответ и отказ валидации. Vite предупреждает о крупных чанках карты/PDF; сборку это не блокирует.

В браузере проверены частичная оплата и отклонение переплаты, повторный GPS-импорт, кабинет водителя, мобильные формы счетов/осмотров/POD. Ширина документа на 375 px равна 375 px; контрольная проверка на 1440 px также без переполнения. Кнопка POD имеет высоту 43 px. API документов отдельно проверено реальным HTTP-запросом: PDF сохраняется и открывается без изменения байтов; неподходящий файл получает HTTP 415. Браузерная автоматизация выбора файла зависла, поэтому её результат не засчитан как успешная проверка загрузки.
